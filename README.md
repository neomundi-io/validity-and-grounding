# Validity and Grounding

**Evaluate the factual validity of a generated response without confusing it with its real-time stability.**

This public research repository is dedicated to experimental methods for evaluating factual validity, semantic risk and the grounding of responses generated by AI systems.

It is part of the **NeoMundi Research** initiative.

The central question is simple:

> **How can the factual validity, semantic risk and documentary grounding of an AI-generated response be evaluated independently from its stability during execution?**

---

## 1. Objective

Generative AI systems can produce fluent, coherent and stable responses while still being factually incorrect or insufficiently grounded.

NeoMundi therefore distinguishes several complementary signals:

- **real-time generation stability**, meaning the system’s behavior while the response is being produced;
- **factual validity**, meaning the probability that generated claims are correct;
- **grounding**, meaning whether a claim is supported by a provided documentary corpus;
- **hallucination risk**, meaning the risk that a response contains unsupported, fabricated or semantically fragile claims.

> **Stable does not mean true.**

The objective is not to produce a single opaque score.

The objective is to document distinct, interpretable and auditable signals that can be combined according to the governance context.

---

## 2. Separating stability from validity

A response can be stable but false.

A response can also contain factually useful information while displaying generation instability.

NeoMundi therefore separates two methodological layers:

```txt
G = real-time generation stability signal
V = factual validity and grounding signal
```

This separation prevents behavioral stability from being confused with factual accuracy.

In practice:

- **G** helps determine whether generation remains stable during execution;
- **V** helps determine whether the generated content is factually supported;
- both signals can be combined within a governance architecture;
- they should not be merged too early into a single score that is difficult to explain.

> **Stability is not truth.**  
> **Grounding is not governance.**  
> **Responsible governance requires distinct signals.**

---

## 3. Self-hosted Llama as a judge

NeoMundi integrates a **self-hosted Llama judge within a sovereign inference pipeline**.

This architecture makes it possible to execute a critical qualification function on controlled infrastructure without systematically depending on an external inference service.

> **Self-hosted Llama judge within a sovereign inference pipeline.**

The judge can help identify:

- potential factual hallucinations;
- suspicious or unsupported claims;
- semantic tensions;
- exact phrases requiring human review;
- elements requiring additional verification.

This evolution strengthens three fundamental requirements:

- **privacy**, by reducing unnecessary exposure of sensitive data;
- **resilience**, by limiting dependency on external services;
- **operational sovereignty**, by enabling a critical function to run on infrastructure controlled by NeoMundi.

A simplified public output could look like this:

```json
{
  "factual_risk_score": 0.72,
  "semantic_instability_score": 0.15,
  "suspect_phrases": [
    {
      "quote": "Exact substring extracted from the AI response",
      "reason": "Short explanation of why this phrase is considered suspicious",
      "severity": "high",
      "type": "factual"
    }
  ]
}
```

The important principle is that suspicious phrases must be extracted as exact substrings of the original response.

They must not be rewritten or paraphrased.

This makes the signal inspectable by a human reviewer.

## 4. External judges and methodological validation

External models may also be used to:

- compare verdicts;
- measure agreements and disagreements;
- prepare methodological reviews;
- perform cross-checks;
- contribute to multi-judge validation.

These external models are not necessarily a unique source of truth.

They may serve as complementary layers for comparison, arbitration or validation.

The objective is to reduce dependency on a single judge and make uncertainty zones more visible.

---

## 5. Cohere as an optional grounding module

Cohere may be used as an optional grounding module.

Its role is different from that of the self-hosted Llama judge.

The judge helps qualify the factual and semantic risk of a response.

The grounding module checks whether claims are supported by a specific documentary corpus provided by the user or client.

This mechanism is particularly useful in contexts such as:

- legal AI;
- document automation;
- compliance workflows;
- enterprise knowledge bases;
- medical or technical documentation;
- internal assistants based on policies or procedures.

A simplified public output could look like this:

```json
{
  "grounding_score": 0.84,
  "is_grounded": true,
  "citations": [
    {
      "document_title": "Example document",
      "text": "Relevant passage supporting the claim"
    }
  ],
  "ungrounded_claims": [
    "Claim not found in the provided corpus"
  ]
}
```

The grounding module is optional.

It is relevant only when a reference corpus is available.

## 6. Conceptual architecture

The validity and grounding layer can be understood as an evaluation layer running in parallel with the real-time stability signal.

```txt
User prompt
    ↓
LLM response
    ↓
Validity and grounding qualification
    ├── Self-hosted Llama judge
    │   ├── factual risk
    │   ├── semantic tension
    │   ├── suspicious phrases
    │   └── elements requiring verification
    │
    ├── Optional multi-judge comparison
    │   ├── agreements
    │   ├── disagreements
    │   └── methodological arbitration
    │
    └── Optional Cohere grounding module
        ├── grounding score
        ├── supporting citations
        └── unsupported claims
```

> **Measure. Qualify. Verify. Interpret. Govern.**

This repository does not define NeoMundi’s complete real-time governance engine.

It documents the public research layer dedicated to factual validity and grounding.

---

## 7. Interpretation example

A generated response may receive the following profile:

```txt
Real-time stability: stable
Factual validity: low
Grounding: insufficient
Hallucination risk: high
```

This means that a response may appear fluent and coherent while still requiring review because its claims are not sufficiently supported.

This distinction is central to responsible AI governance.
